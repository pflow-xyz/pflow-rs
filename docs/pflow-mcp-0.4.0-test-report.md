Date 2026-11-03. Subject: the npm package `@pflow-xyz/pflow-mcp@0.4.0`, byte-identical to the local build
(`target/npm/pflow-mcp`, built from pflow-rs `836be2d`; `server.mjs`, both engines and `hosted-tools.json`
compared with `cmp`). Testing only: nothing was published to npm, pushed or version-bumped. Work is on local

How the tests are kept honest: reachability is compared with an independent BFS written in the test (state and edge
counts, deadlocks, L1 and L4 liveness, witness replay); every reported P- and T-invariant is checked against an
incidence matrix computed from the net by the test; SSA and SDE are compared double by double with go-pflow's
portable goldens; known-good CIDs are compared with the `z4EBG9j…` file names in `pflow-xyz/examples`. A check marked
`known` is a documented bug or rough edge, so the suite goes red only on something new.

## What works (verified)

- All 33 tools are present, with the documented names. Server start is ~290 ms, the first `chyp_check` 9 ms, the first `ontology_classes` 100 ms (lazy load).
- **SSA is byte-exact with go-pflow**: all 6 portable goldens (chain, sir, dimer, coffeeshop, gates, timed), every double equal. Same seed gives identical bytes; a different seed differs; tokens stay integral and conserved; 200-run SSA mean tracks the ODE (R 86.5 vs 86.3).
- **SDE matches go-pflow** on the 3 goldens a plain net allows (chain, dimer, sir); coffeeshop and gates are refused (capacity, read/inhibitor arcs), as documented.
- **Reachability verdicts agree with the reference BFS on every complete search** (24 synthetic nets compared; for the 18 complete ones states, edges, deadlocks, L1, L4 and boundedness, for the 6 truncated ones the rule that no verdict is `true`), and every witness replays on the reference semantics. Incomplete searches never claim a `true` verdict.
- **Invariants**: every reported P- and T-invariant is a true invariant of the reference incidence matrix, with the right marking value, on the 34 array-shape nets (the JSON-LD documents are converted back by the test only for the other tools).
- `verify` proves, refutes and returns replayable counterexamples correctly (mutual exclusion proved structurally from `crit1 + crit2 + lock == 1`, refuted on the broken mutex; philosophers' deadlock refuted with the trace `takeL0, takeL1, takeL2`).
- CIDs equal pflow.xyz's for the three published example documents; `edit` is all-or-none; `bundle_*` replays all four `bundle_example` scenarios, including the three that are meant to expose documented saga limits.
- Refusals are clean for guards, stages, rate schedules, bad arcs, duplicate ids, negative marking, negative rate: `isError`, a reason, and no half-loaded net left behind.
- `artifact_html` is XSS-safe against hostile titles and place ids.

## Bugs and correctness issues, worst first

### B1. High: a large `max_states` overflows the wasm stack and kills the server for good
`reachability` (and hosted `verify` / `validate` with reachability) with `max_states` of about 15 000 to 20 000 on a
large incomplete state space throws `Maximum call stack size exceeded`. The first overflow comes back as the
misleading `attempted to take ownership of Rust value while it was borrowed` (server.mjs `try { … } finally { n.free() }`
frees a net the trap left borrowed). **After two such calls every call fails with `memory access out of bounds`, including
`load_net` and `check`, until the process is restarted.** `spread-8x12` (50 388 states) overflows at 20 000 in 1.3 s;
`toggles-16` (65 536 states) overflows between 14 000 and 16 000. 20 000 is the documented maximum, and a stack overflow
sits at the heart of the advertised range.
- Repro: `test-corpus/repro/stack-overflow-poison.mjs <pkg dir>`.
- Suspected cause (not instrumented): `detect_cycles` calls the recursive `dfs_cycles` (crates/pflow-reachability/src/analyzer.rs, ~line 876) with `String` keys, so depth grows with the length of a DFS path through the state graph; the SCC pass beside it is already iterative.
- Fix: make `dfs_cycles` iterative; keep a depth/state budget; in `server.mjs` catch a `RuntimeError`, re-initialise the engine (or exit so the client respawns it) instead of staying poisoned, and never call `free()` in a `finally` after a trap.

### B2. High: `artifact_html` pages cannot draw the ODE chart
The generated page does `res.series[p].values || res.series[p]`. For ODE results `series[p]` is an array, and
`Array.prototype.values` is a function, so the code takes the function and throws
`function is not iterable (cannot read property Symbol(Symbol.iterator))`. Every page opens with an error line and an
empty chart, and **Run ODE does nothing**; only Run SSA works (its series are objects with `.values`). Reproduced in
headless Chrome and in the real claude.ai artifact viewer (`…/HMigW6ELfJRYLeQ8V3eKeQ`). The test suite never executes
the page (it only runs `node --check` on its script). Fix: `Array.isArray(s) ? s : s.values`, and add a headless-browser
smoke test (see Embedding below).

### B3. Medium: the 18 hosted-name tools cannot read what `load_net` accepts
`load_net` takes the array shape (`places: [...]`, `arcs: [{from,to,weight,type}]`, the shape of every sim.pflow.xyz
model and of the README's own example). `check`, `info`, `incidence`, `invariants`, `validate`, `verify`, `export`, `cid`
and `what_if` take only pflow.xyz JSON-LD. Passing the **name of a loaded array-shape net** (the documented convenience)
fails with `net.places: an object keyed by place id (this looks like the flat net pflow_bundle_flatten returns, …)`,
which blames the wrong thing; `sde` fails with `missing field source`, `edit` the same. A loaded net therefore gets
`simulate`, `stochastic` and `reachability` but no proofs, unless the caller converts it by hand (`test-corpus/lib.mjs:toJsonLd`
does). `state` includes `info` only for JSON-LD nets. `Net` accepts JSON-LD, so the cheap fix is to store JSON-LD on
load (or convert in `resolveNet`). (Another run, 520d030a, is adding `bundle_net`, which closes the same refusal for composites.)

### B4. Medium: rate 0 means "unset"
`simulate({rates:{d:0}})`, `stochastic({rates:{infect:0}})` and a model transition with `"rate": 0` all behave as if the
rate were the default (the SSA ran with the net's 0.3; the zero-rate transition fired). `1e-9` works. "Switch this
transition off" is the most common what-if (the vet clinic's own `no_surgery` disruption is exactly that), and it cannot be
expressed. sim-pflow-xyz's model text already warns about it ("a transition-level 0 would read as unset"). Use `null` for unset.

### B5. Medium: `cid` / `export` / `edit` are about cubic in net size and block the server
Timings for a chain of N places and N transitions: N=10 0.04 s, 25 0.15 s, 50 0.8 s, 100 6.1 s, **200 53 s** (the single-threaded
URDNA2015 canonicalisation; every other tool call waits). The 40-place vet clinic takes 1.3 s. `edit` returns a CID on every
call, so editing a 100-node net costs ~6 s per call. Fix: canonicalise lazily (`cid: false` on `edit`), cache, or run it in a worker.

### B6. Low to medium: the CID names a document, not a net
Reversing the arc list, moving a node (`x`, `y`), renaming the net or adding a description each change the CID; reordering
the `places` / `transitions` keys does not. `export` does not normalise arc order. That is consistent with
pflow.xyz, but the README says "the CID a net seals to". Consider `cid({semantic:true})` that sorts arcs and ignores layout and
labels, so two copies of one net agree.

### B7. Low: smaller defects
- `reachability`: `states` can exceed `max_states` (2001 for 2000, 10003 for 10000). Time is superlinear (toggles-16: 2 000 states ms; 5 000 0.7 s; 10 000 3.8 s; 12 000 6.6 s), with no time budget.
- `load_net` needs `name` inside the model: `{places,transitions,arcs}` without one fails with `missing field name` even when `load_net`'s own `name` is given, although its description says the name defaults to the model name "else net".
- Fractional arc weight: `load_net` refuses it (`invalid type: floating point 0.5, expected i64`, no arc named) but `check` / `invariants` / `incidence` silently truncate it to 0.
- `invariants` returns `p_invariants: null`, not `[]`, when there are none.
- `reachability` and `verify` disagree on a net that drains to the empty marking (documented in the tool texts, but a consumer sees `deadlock_free: false` and `proved` for the same net).
- `sde`'s refusal tells the caller to use `pflow_ssa`, which does not exist locally (`stochastic` is the equivalent). `what_if` on a 200-place net hits the hosted 61 440-byte cap although the README says that cap is not applied.
- `bundle_example` returns `scenarios` whose `expect` items carry `op: "=="`, and `bundle_run` rejects `op` (`unknown field "op"`), although its own output echoes `op`. Scenarios cannot be fed back verbatim.
- chyp: `chyp_check` reports a failed rewrite step only as `status: "invalid"` on its parts; `errors` is empty (parse errors only) and no part says why. A step cited `by` the wrong rule makes the whole theorem and its `qed` invalid with 5 red parts. `chyp_part` with an index out of range answers `null` with `isError: false`.
- `list_nets` has a 16-character description; `artifact_html`'s default path is a fixed temp name per net.
- `empty` net (0 places) loads and analyses as one dead state without a warning.

## API naming and rough edges

- `load_net(model)` but every other tool says `net`. `net` is a name (string) for the local tools and a name *or* a JSON-LD object for the hosted ones.
- Mixed casing in one server: `tEnd`, `maxPoints` (simulate), `max_states`, `max_tokens` (reachability), `t_end`, `what_if` (hosted).
- Two net shapes are accepted by different tools (B3), and `state` only sometimes carries `info`.
- Verdict vocabulary is split: `quasi_live` / `live` (reachability) versus `live` / `l4-live` (verify). `live` means L4 in one and L1 in the other.
- `chyp_*` tools have no relationship to the net tools; nothing derives a theory from a net or bundle.

## Embedding: prototypes and measurements

Pages built by `publish/build.mjs` from the 0.4.0 package. Each is one file; wasm is gzip+base64 inflated with
`DecompressionStream`; engines are wrapped in function scopes so two builds that both define `Net` coexist.

| Page | Engines | Raw | gzip | Median load in headless Chrome (file, offline) | Notes |
|---|---|---|---|---|---|
| `artifact-html-0.4.0-baseline` | small | 248 KB | 177 KB | 97 ms | current output; ODE chart broken (B2) |
| `explorer-small` | small | 278 KB | 184 KB | 128 ms | plain-language verdicts from `reachability` only |
| `explorer-full` | hosted | 981 KB | 711 KB | 180 ms | + structural proofs, invariants, what-if, console for all 18 hosted tools |
| `explorer-both` | small + hosted | 1 223 KB | 885 KB | 221 ms | the small engine adds 242 KB and nothing the hosted one lacks |
| `saga-proof` | hosted + chyp-rs | 1 097 KB | 802 KB | 236 ms | bundle glue check, 4 scenario replays, Chyp rewrite proof re-checked in the page, with diagrams |

**Offline**: every page was loaded in a Playwright browser context with `offline: true`; zero non-file requests, zero page errors, in
light and dark and at 400 px (no horizontal scroll). **In the real artifact sandbox** (claude.ai viewer, iframe `sandbox="allow-scripts
allow-same-origin allow-forms allow-pointer-lock allow-popups"`) all five pages run: wasm instantiation works (no CSP blocker found), `DecompressionStream`
works, 1.2 MB pages are accepted, the second wasm module (chyp) loads, and the proof page re-checks live (Break one step turns 5 parts red). Engine ready
times inside the sandbox (Mac Chrome): small 124 ms, full 197 ms, second engine 24 ms, 212 ms to a rendered page. The in-page "network
requests" counter reads 1 to 2 there; those are resource entries of the viewer frame (the page code has no URL in it), and the page
cannot be inspected from outside the cross-origin frame, so this is not a proof of zero requests in the sandbox. No blockers found. Not tested:
Safari, the claude.ai mobile app, other sandboxes (Claude Desktop artifact pane).

### Recommended embed design

1. **Embed the full engine only.** It contains `Net` (everything the small engine does), costs +703 KB raw over the small one but only ~50 ms, and is
   what lets a page prove things (SIR: small can say only "checked 2 000 situations, then stopped"; full proves "nothing piles up without limit" and "100 tokens in total"
   structurally). `both` is strictly worse than `full`. Keep the small engine as an opt-in `engine: "light"` for pages that only play and plot.
2. **Page = verdicts first, play second, console last.** The prototypes put "What can be proved" (plain-language ✓ / ✕ / ?, each with a "How this was
   checked" disclosure holding the raw evidence) above the token game and the charts, derived from `verify` + `invariants` at load. Counterexamples are
   firing sequences, so the page can offer a "Replay this" button (not built).
3. **Parameterise `artifact_html`** with `claims` (properties and their plain-language titles), `intro`, `scenarios`, and `engine`. Move the wording tables
   (`KIND` in `client-net.js`) into the package so every page says the same thing, or add an `explain` tool that returns verdict text.
4. **Composites and proofs**: `saga-proof.html` shows the shape: bundle glue check, scenario replays with `says` text, one Chyp theory with its
   diagrams. The page is honest that the net checks and the Chyp theory share only step names. Needed to make this real: `bundle_to_chyp` (generators from transitions
   and ports, rules from links and the compensation pattern) so the theory is derived from the model, plus a "this theorem is about these steps" link that is machine-checked.
5. **Weight**: the wasm is stored as gzip then base64 and the page is then gzipped again (981 KB raw, 711 KB gzip), so transport compression buys little. Smaller levers: `wasm-opt -Oz`, strip
   names, drop the two unused wasm exports, or ship the hosted engine without `Net` duplicates of `reachability` code.
6. **Test the page, not its script**: add the Playwright harness used here (`offline: true`, request log, console errors) to `make wasm-mcp-test` for `artifact_html`;
   it would have caught B2.

## Proposed features for the next version

1. One net shape end to end: normalise in `load_net`; `state` / `info` / `export` for any loaded net; `export` formats `jsonld`, `simple`, `svg`; rename `load_net(model)` to accept `net` too; unify `snake_case`.
2. Robustness: iterative DFS (B1); a time budget (`timeout_ms`) on `reachability`, `validate`, `verify`; run the engine in a worker thread so a trap restarts the worker, not the server; `cid: false` on `edit`.
3. Rate `null` for unset, `0` meaning off (B4); a `scenario` argument on `simulate` / `stochastic` (rate schedules, marking overrides) so the sim.pflow.xyz what-ifs run offline.
4. `artifact_html` v2 (above): verdicts, replay, the CID on the page when cheap, light/dark, a "copy proof as text".
5. `explain`: verdicts to plain language, for pages and for the model's own replies.
6. `bundle_to_chyp`; chyp reasons for invalid steps; `chyp_check` returns `ok` and the first failing step; an in-page Chyp panel in `artifact_html` for bundles (prototype exists).
7. `reachability` with `target` (is this marking reachable?) and a witness replay in `artifact_html`; a state budget by memory, not only count.
8. Add this suite (`test-tools.mjs`, `test-corpus/`, the page smoke test) to `make wasm-mcp-test`; run it against the npm tarball in CI.

## Known issues recorded in the suite (all 21)

Each is a `known:` check in `test-tools.mjs`; the `FAIL` status appears if one of these is fixed and the check is left marked known, or if anything new breaks.
`net` type differs across tools; `load_net` needs the model's own `name`; `states` can exceed `max_states`; rate 0 (two checks); hosted tools refuse the array shape (three checks, plus `sde`);
fractional weight accepted by hosted tools; reachability vs verify on a draining net; CID depends on arc order, layout and name (three); `bundle_run` rejects `op` (four, one per scenario); chyp invalid steps have no reason; `chyp_part` out of range returns null; `cid` of 200 places takes 53 s.
Not in the suite, because they poison the process: B1 (`test-corpus/repro/`).
